# Agentic Life World Studio — PRD 1.2

狀態：2026-10-27，作者已確認六項設計，v0.06 實作規格。舊八模組、完整世界模擬與逐條設定審核方案已由本規格取代，保留於 [PRD 1.1 歷史封存](archive/PRD-1.1-historical.md)，不代表目前產品需求。發布狀態以 README／release 為準。

## 1. 產品與使用流程

作者匯入原作，AI 整理一份精簡創作簡報；作者核對少數關鍵裁定、確認視覺試稿，建立可持續出版探索影像與觀察日誌的網站。訂閱、明信片與美術集延用已出版素材。產品不要求先建立完整故事百科、遊戲規則或世界模擬器。

**萃取判準：這條資訊會改變公開畫面、旅行敘述或延伸創作界線嗎？** 不會就略過。不得硬編故事設定、固定角色、物種、地理數量、災變原因或攝影風格。

1. 匯入文字／Word／PDF／網址及選填參考圖；保留原文，明示未自動擷取全部內嵌圖片。
2. AI 分段閱讀，只保存對六項簡報有用的精簡線索，不列人物關係、完整劇情、物品清單及逐句疑義。
3. 統整六項、形成一個可用的視覺方向，由獨立忠實度角色核對相關原文與參考圖。
4. Studio 顯示 AI 填好的六段草稿，只有關鍵缺漏、實質矛盾或必須由作者選擇的創作界線才提問。未知與不適用合法，不為湊欄位提問。
5. 作者可直接修改／以對話補充；未儲存、版本衝突與未答必要問題會阻止核准。勾選本人確認並送出才成立設定核准。
6. 以預填的視覺方向產生試稿，作者確認後才能啟用。設定核准、視覺核准、啟用分開，均綁定目前內容版本。

## 2. 六項資料契約與作者介面

`WorldBrief` 是新增的 runtime 契約，版本 `world-brief/0.06`。六項各為一段可編輯文字（每項最多 4,000 字元）；AI 必須先填好，不要求作者從空白表單建構世界。

| key | 畫面名稱 | 保留的內容 |
|---|---|---|
| world | 世界的基本樣貌 | 名稱、年代、塑造現況的關鍵背景，以及影響可見景象的文明／環境／生命特徵 |
| visual | 一致的視覺風格 | 原作配圖與外觀線索、媒介、材質、光線、整體觀看感受 |
| viewpoint | 觀看者與敘述聲音 | 原作人物／新旅行者／不具名觀察視角，必要外觀、語氣、讀者與呈現尺度 |
| time | 旅程時段與揭露界線 | 旅程位於故事哪個階段、能否推進時間、不可揭露的事件與結局 |
| naming | 命名與必要專有詞 | 少數必要原名、地點／生命的命名語感、重要中英日名稱原則 |
| boundaries | 延伸創作範圍 | 不可改動的核心、可衍生的景觀／生命／旅行小事件，以及具體禁區 |

必要裁定 `decisions` 最多 5 題，每題含穩定 ID、所屬六項、具體問題、AI 建議與作者回答。AI 建議不等於回答，解析／審核結果的回答一律留空。沒有必要裁定就直接顯示草稿確認，不創造問題。技術失敗使用可恢復的處理對話，不偽裝為創作問題。

私有 metadata 包含參考圖讀取狀態與少量已核對的原文依據，供追溯和忠實度檢查；不是作者必填欄位。六段內容與裁定為草稿，整份尚未核准前都不得啟用。

中央元素庫保留穩定 ID、多語名稱、公開定義與外觀特徵，隨後續探索逐步累積。不要求先萃取整篇小說所有人物、物品與組織；只有成品會使用的已知名詞需要保留。日期、日誌編號、網站分類、版型與更新頻率由出版／營運設定管理。

## 3. Multi-agent 職責與忠實補全

所有推理延用部署端 Meta 模型呼叫，參考生成延用 Muse Image。provider 憑證只在部署端，不把模型或內部流程寫入公開內容。

| 角色 | 輸入與責任 | 禁止事項 |
|---|---|---|
| 精簡閱讀者 | 原文片段；只取六項相關線索與可定位依據 | 全面列人物／關係／物件、逐句爭議、替作者回答 |
| 創作簡報編輯 | 全部精簡閱讀筆記；先填好六段，最多 5 個必要裁定 | 因缺少非必要資訊而加問題、把補全冒充原文明示 |
| 視覺導演 | 簡報及實際參考像素；產出一個相容的預填視覺方向 | 強迫選三種畫風、沒有像素卻宣稱已讀圖 |
| 獨立忠實度審核 | 簡報、已核對原文段落及必要參考圖；修正實質誤讀、彙整少量重大裁定 | 全文劇情評分、微小引句差異變作者工作、簽署核准 |

六項初始化解析每次 Queue delivery 最多一個角色呼叫。此解析流程的完成結果先持久化，checkpoint／用量帳本可恢復；重試不重付已保存的有效解析結果。既有視覺與翻譯延用其現行執行流程，本版不將此解析承諾擴及所有出版工作。不因單一格式問題清除所有閱讀進度。

延伸內容的邊界由作者在初始化核准。日常在核准範圍內生成，不要求逐篇回來批准；改動核心或範圍外內容必須重新提案。沒有核准範圍不視為自由生成授權。

## 4. v0.06 MVP、相容與驗收

- 交付：六項解析、AI 預填、必要裁定、設定確認、視覺試稿及既有翻譯／預覽／發布串接。公開預設英文，沿用 en／zh-Hant／ja 校準能力。
- 後續：每日自主探索、訂閱寄送與美術集排程仍屬後續，不宣稱本版已常態運營。
- 舊原文、核准與發布快照保留；舊進行中工作按其原版本完成。新匯入與作者主動重新整理才使用六項流程，不自動重跑既有 IP。
- 舊未核准草稿可由本人明確選擇六項重新整理；不能把舊八模組核准冒充新簡報核准。舊已核准世界保留可讀及既有發布相容。
- 新簡報不得要求既有元素清單或探索起點 ID，沒有已知物種／地點也能確認。私有 metadata、來源、裁定與核准不進公開 DTO。
- 圖片容量延用單張 5 MiB、合計 15 MiB、最多 6 張；預填方向不等於視覺影像已核准。
- 驗收：兩種無共通故事設定的中性原作可得到同一份六項契約；無關劇情不進結果；沒有重大缺漏就不提問；裁定／修改／競態阻擋有效；重試、用量 audit、公開投影與雙環境版本一致。
- 發布只走 GitHub main → checks → dev schema／Worker／frontend → readback → production 同步 → readback；docs-only 不觸發部署。
