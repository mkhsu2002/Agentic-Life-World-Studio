# 世界框架與忠實補全｜v0.03 設計草案

狀態：2026-10-27，待使用者確認，尚未實作。產品維持 v0.02；本文件不代表現有 API、資料庫或 Agent 已支援新框架。

## 1. 設計目的與取捨

第一個 Agent 必須讀懂「這是怎樣的世界」，篩掉不影響世界建構的情節細節，再將具體工作交給專業角色。產物是一份作者能理解、修改、核准的世界方案，而非原文所有名詞與引句的彙整。

三種方法的取捨：逐句建百科容易淹沒重點；直接生成世界摘要容易漏掉約束與相互關係；本案採用**固定的通用框架＋動態元素與關係＋私有來源依據**，兼顧可確認與可運行。

「忠實補全」指：保留核心，將必要但原作未定的細節列成提案，經作者初始審核後才納入世界。不得由模型自行判定「合理」就當作已獲授權。

## 2. 最小世界框架：八個內容模組

這些是系統必須判讀的面向，不是作者必須手填的八張表。AI 先填方案；原作未提及就保留未知，確定不適用則標示不適用。模組數不是世界內元素數量的限制。

| 模組 | 最少欄位 | 要解決的問題 |
|---|---|---|
| 1. 世界識別與核心定位 | `world_name`、`source_title`、`premise`、`defining_traits`、`scope` | 世界叫什麼？核心特色是什麼？這次建立哪個範圍？作品名不自動等於世界名。 |
| 2. 時代、變遷與現況 | `temporal_frame`、`formative_changes`、`present_condition` | 處於什麼年代？哪些歷史變化塑造現在？允許相對年代、循環或非線性時間，不強制西元。 |
| 3. 世界運作法則 | `capabilities`、`conditions_and_costs`、`limits`、`invariants` | 有什麼能力、技術或特殊現象？在何種條件下成立？不能發生什麼？普通現實世界也有其限制，不強迫新增超常能力。 |
| 4. 空間與區域差異 | `places`、`containment`、`connections`、`regional_distinctions`、`access_conditions` | 哪些地方存在？如何包含、相鄰、連通或隔絕？區域差異來自何處？不強制國界、固定層數、平面地圖或經緯度。 |
| 5. 環境與感官條件 | `local_conditions`、`cycles`、`hazards`、`landscape_character` | 空氣或其他介質、光、氣候、地貌、可見度如何？何者塑造生活條件與畫面？只填相關條件，不默認有空氣、季節或重力。 |
| 6. 生命、行動者與生態 | `life_or_actor_types`、`form_and_scale`、`habitats`、`behaviors`、`dependencies`、`interactions` | 什麼在活動？外形與尺度如何？如何生存、互動並回應環境？可容納人類、非生物行動者；不強迫每個世界有生態系或怪物。 |
| 7. 文明、文化與人造物 | `communities`、`ways_of_life`、`built_environment`、`technologies_and_objects`、`resources_and_constraints` | 居民如何生活？建築、設施、物品與資源呈現什麼文明狀態？制度、技術可有區域差異，不用單一科技等級概括所有文化。 |
| 8. 視覺規範 | `reference_assets`、`medium`、`shape_material_scale`、`color_light_atmosphere`、`regional_variants`、`visual_invariants`、`forbidden_motifs` | 世界應如何被看見？哪些特徵必須一致，哪些可隨地點與時間變化？媒材不強制攝影寫實。 |

每一模組都要有「本世界的重要性判斷」與可理解摘要。低影響內容留在可查來源，不必進入核心設定或作者確認表。年代、災變、技術、氣候、生物外形都不能由題材標籤自動補出。

## 3. 貫穿所有模組的元素與關係

中央元素庫統籌地方、生命、群體、角色、物品、設施、現象與概念。這些只是可用類型，具體分類依原作建立，不是固定必備清單。

每個元素至少記錄：穩定 ID、動態類型、原名與別名、關鍵定義、所在範圍、關係、固定特徵、允許的變體。名稱、特色與關係共用 ID，避免同一元素在地圖、圖鑑、作品與譯文中各自生長成不同版本。

命名是橫跨世界的規則：世界／地域／生命／物品的命名慣例、語感、構詞、音譯或意譯政策、大小寫與禁用形式。原作只提供零星名稱時，不自行宣稱已有完整命名規則；先提出建議供作者核准。

多語系名稱保存 `locale → name/aliases/description` 與各自版本、審核狀態。公開預設 `en`，初期目標 `en／zh-Hant／ja`。原始資料可以任何語言建立；英文不是世界真值的唯一來源。翻譯不能新增特色，未核准語系不能因快取有文字就視為上線。

關係至少能表達「在哪裡」「依賴什麼」「影響什麼」「在何種條件下成立」。生命出現、區域條件與人造設施要能彼此約束，不能只存名稱與外觀。關係也須保留依據、範圍與效力時間；未經證實的因果只能是候選。

空間層級數與詞彙動態。局部設定繼承適用的上層約束；例外須有已核准依據，不能以局部描述悄悄覆寫世界核心。

## 4. 另設兩組運行設定

這些設定決定「如何讓人探索這個世界」，與世界自身的真值分開保存。

| 設定 | 最少欄位 | 邊界 |
|---|---|---|
| 受眾與觀察方式 | `audience_intent`、`tone_and_intensity`、`focus`、`observer_profile`、`knowledge_boundary`、`disclosure_policy`、`intervention_policy` | 受眾輪廓由 AI 建議、作者確認，不從題材猜測精準年齡或人口屬性。焦點可選風景、生命或兩者；觀察者不必是原作角色，也不能因此成為全知者。 |
| 起始狀態與變化邊界 | `start_time`、`start_place`、`initial_conditions`、`state_variables`、`allowed_transitions`、`event_triggers` | 指定從何時何地開始、哪些狀態可變、什麼條件會引發什麼變化。依可觀察尺度建模，不承諾完整物理或生態模擬。 |

排程、預算、網域、部署、訂閱與發布頻率屬網站營運設定，不混入世界正典。v0.03 首先建立上述政策的設計與確認能力；持續模擬與自主出版仍是後續實作範圍。

## 5. 設定、狀態、觀察三者分離

- **設定：**某類事物有哪些穩定特徵與限制。
- **狀態：**某個地點或個體在特定世界時間發生的變化。
- **觀察：**某位觀察者在該處能看見、聽見或可靠得知的內容。

一個個體的一次行為，不自動成為全物種的通則。尚未探索，不代表不存在；尚未知道，不代表允許自由創造。事件可改變狀態，不能改寫不可變設定；圖片偶然生成的細節也不能倒灌成世界真值。

## 6. 初始審核：作者實際確認什麼

Studio 先呈現一張已填好的世界總覽，再按需展開八個模組。每個重要項目呈現「目前理解／原作依據摘要／建議補全／影響／可編輯選項」，讓作者一次確認一份整合方案。

初始核准包包括：

1. **核心錨點：**不能變動的年代關係、法則、區域特徵、形態、專名與視覺特徵。
2. **具體補全清單：**原作未定而本次準備加入的設定、理由、依據、依賴、界線與作者決定。
3. **後續生成範圍：**允許變動的欄位、值域或模板、適用範圍、命名規範、禁止變更及失效條件。只有作者看得懂、足以判定違規的範圍才可授權；空值不代表無限制。
4. **視覺校準：**實際可讀的原作圖像、來源文字、風格方案與試稿的差異。未取得圖片像素時必須標示未檢視，不得靠 alt、檔名或正文冒充看過圖片。
5. **探索與揭露政策：**時間切片、起點、可知範圍、劇透與可介入程度。

作者可整包核准、修改或保留部分待確認。核准是對該版本的具體內容與範圍，不是一個籠統的「AI 可以補全」開關。

日後只能在初始明確核准的範圍內具體化與產生狀態變化。新增地區、物種、法則或改變核心特徵，若未被該範圍明確涵蓋，就留在 Studio 提案，不送前台。擴大範圍或修改核心必須由作者明確建立新版本並重審，原版本不可覆寫。

## 7. 遇到缺漏與疑義的處理

先判斷對世界的影響，再決定是否需要打擾作者：

- 排版、字形或不影響設定的引句差異：系統修復來源定位，保存警示，不變成作者必答題。
- 非核心、目前也不需要的未知：保留未知，略過該項，不阻止其他可完成的工作。
- 影響年代、法則、區域、形態、視覺或生成權限的矛盾：集中進首次確認表，給建議與可編輯選項。
- 原檔或圖片無法讀取：保留其他閱讀成果，精確說明缺哪一部分；不能把不可讀當已讀完。

工作依賴被阻擋時停該分支，其他獨立分支可繼續；保留 checkpoint，作者回覆後只重做受影響的部分。任何候選引用修復都不得捏造原文。若高影響主張失去可靠依據，必須重新查證或交作者明確補充，不能靜默降級後仍當作原作事實。

## 8. 公開輸出與最小啟動門檻

前台呈現已審核的世界與探索成果；不顯示哪些設定是補全、內部信心、Agent 討論、來源全文、prompt、核准與稽核紀錄。內部欄位從公開 DTO 白名單排除，不能只靠 UI 隱藏。所有語系、SEO、ARIA、alt 與圖片可讀文字都適用。

每個模組的判讀狀態必須明確，但不要求每個模組都有實體。啟動某次探索所需的最小條件是：

- 一份已核准的核心設定與補全／生成範圍，沒有影響該次探索的未解重大衝突。
- 一個有效的起始時間／順序與可定位範圍，一個可觀察對象；對象可以是地景、現象、生命或物件。
- 已核准的視覺規範及代表性試稿；來源不可讀的限制已如實告知並由作者決定如何處理。
- 已確認的觀察視角、可知與公開邊界；初始狀態符合設定與關係約束。
- 公開英文所需名稱與內容已核准；其他語系按各自核准狀態啟用。

未觀測的遠方與非必要未知可保留，但不得假稱它們已完成編譯。第一個可探索區域的就緒與全來源閱讀覆蓋是不同指標；部分就緒不可冒充完整閱讀。
